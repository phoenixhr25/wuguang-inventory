# 产品说明

## 问题

用户往往看不清自己已经拥有什么：重复购买、忘记已有物品、长期闲置，也难以理解物品总价值和使用效率。

传统库存工具像 ERP，字段多、维护累。物光的产品假设是：如果入口从照片开始，并让系统逐渐承担识别和整理工作，个人物品库才可能被持续维护。

## 核心闭环

```text
照片或手动添加
→ 确认名称、分类、数量和金额
→ 形成个人物品库
→ 查询、发现相似和记录使用
→ 得到搭配或处置建议
→ 实际使用并反馈
```

## 当前版本的定位

当前一级导航围绕“记录它 → 使用它 → 记住它”组织为“物品库｜怎么用｜关于它｜数据与备份”。物品库与“怎么用”均按衣物、其他物品和数码组织。“其他物品”按主要用途收敛为个人护理、运动户外、书籍文具、兴趣收藏、工具器材、生活用品和其他，旧家居记录统一归入“生活用品”继续兼容。

“怎么用”的入口顺序为衣物、数码、物品；“物品”是“其他物品”的简短界面名称。其他物品每次主动点击都会追加使用事件，同一天可以记录多次；页面分别展示近 30 天使用次数、使用覆盖率、各子类覆盖率、最近使用间隔、待处理列表和最近事件。单件物品可以标记使用中、收纳中、待处理或已离开，并记录一次简单维护；没有使用记录只显示为“没有记录”，不自动判断闲置。该模块不包含借出和归还。

“关于它”采用双入口：在单件物品编辑页填写同一个可选故事字段，在集中页面回看、补写并生成 PNG 故事卡。故事卡默认只包含照片、名称、分类、故事和物光标识，不包含金额与收纳位置。

当前版本是用于验证闭环的本地 MVP，不是完整商业产品，也没有接入 AI。它重点验证：

- 用户是否愿意从一件物品开始；
- 哪些字段最影响录入；
- 用户是否会再次查看库存；
- 基础穿搭与使用记录是否能提高已有物品利用率；
- 完整备份是否足以支撑早期试用。

## 产品原则

- AI 负责降低录入成本，用户保留最终确认权；
- 不把估算金额冒充真实购买价格；
- 不把“没有记录”直接判断为“闲置”；
- 推荐只能使用真实库存中的物品；
- 数据必须可导出、可恢复、可删除；
- 先验证行为和价值，再建设复杂账户与商业系统。

## 关键产品判断：组合生成之后，真正的问题是选择

当衣橱中只有 2 件上装和 2 件下装时，基础组合只有 4 种；当上装、下装、鞋履和外套分别增加到 10、8、4、3 件时，完整排列可能达到 960 种。继续增加包袋和配饰后，组合数量会更快膨胀。

因此，“今天怎么穿”不能把所有排列一次展示给用户。产品需要把问题从“系统能生成多少套”转成“用户怎样在几秒内找到此刻适合的一套”。推荐流程应采用：

```text
全部可能组合
→ 场合、天气和季节等硬条件筛选
→ 可选：指定一件今天想穿的单品
→ 排除清洗中、不合适和刚穿过的单品
→ 按适合度、个人偏好和使用效率排序
→ 每次只展示少量候选
→ 收藏 / 穿过 / 不适合 / 换掉其中一件
```

### 最小场合体系

场合是用户最容易理解的第一层入口。当前只保留四个高频且差异明显的选项，降低录入与选择成本：

| 一级场合 | 可覆盖的具体情况 |
|---|---|
| 日常 | 买菜、逛街、普通外出、居家和一般旅行 |
| 通勤 | 上班、上学、一般会议和偏正式工作场景 |
| 健身 | 健身、跑步和其他运动 |
| 聚会 | 聚会、约会、聚餐和看展 |

衣物可多选适用场合，新增衣物默认“日常”。“日常”是完整衣橱入口，不按标签排除或优先单品；通勤、健身和聚会才将场合作为硬约束，例如仅标记“健身”的单品不会进入通勤候选。没有场合字段的旧衣物暂时视为四种场合均可用，避免升级后已有组合消失。未来再由 AI 推测正式度、风格、季节和适用场合，用户只确认低置信度结果。

这一选择遵循场景感知穿搭研究的共同结论：视觉上协调并不等于在特定场合合适，推荐需要将场合上下文纳入兼容性判断。参考 [Theme-Matters](https://arxiv.org/abs/1912.06227)、[Scene-aware Fashion Recommender System](https://opus.lib.uts.edu.au/handle/10453/177283) 和 [Fashion Outfit Complementary Item Retrieval](https://openaccess.thecvf.com/content_CVPR_2020/papers/Lin_Fashion_Outfit_Complementary_Item_Retrieval_CVPR_2020_paper.pdf)。

### 大量组合的交互原则

- 默认只展示前 6 套，并提供“换一批”；
- 支持“围绕这件搭配”，让用户锁定一件单品；
- “帮我选”先执行场合硬过滤，并优先场合更专一的单品；“自己搭”不拦截跨场合混搭，由用户保留最终判断；
- 支持替换组合中的某一件，而不是每次重新开始；
- 支持按最适合、最少穿、最近收藏和历史采用情况排序；
- 只长期保存用户收藏、穿过或明确否定的组合，临时候选实时计算；
- 最近穿过的组合可以降低排序，但不禁止用户再次选择；
- AI 只负责给规则筛选后的候选评分和解释，不能凭空创造库存中不存在的物品。

这一设计参考了 Aether Wardrobe 的候选表和分层筛选、Wardrobe 的标签体系、Hangar 的天气与场合推荐，以及 Wardrowbe 的历史、评分和偏好反馈。它们共同说明：组合规模扩大后，稳定的结构化筛选和反馈闭环比一次生成大量搭配更重要。

## 首轮指标

- 至少录入 1、3、10 件物品的人数；
- 从照片到确认一件物品所需时间；
- 每件物品需要填写或修改的字段数；
- 七日内再次打开比例；
- 查看搭配和记录实际穿着的人数；
- 导出备份的人数；
- 用户最希望自动化的步骤。

进入组合发现阶段后，增加以下指标：

- 用户从打开页面到记录一套穿搭所需时间；
- 选择场合后实际采用推荐的比例；
- “换一批”和“换掉其中一件”的使用次数；
- 收藏后被真正穿着的组合比例；
- 不同场合下重复采用与探索新组合的比例。
