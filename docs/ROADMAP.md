# 路线图与时间预估

时间按一位熟悉代码库的开发者估算，不包含等待用户反馈、平台审核和第三方服务故障。正式排期前应根据验证结果调整。

## 已完成：V0.1 本地 MVP

- 本地物品库、照片、编辑和搜索；
- 基础穿搭与使用记录；
- JSON 完整备份和恢复；
- Streamlit 公网部署。

## 已完成：组合发现 V0.2

- 展示基础组合及包含外套、鞋履、包袋和配饰后的候选数量；
- 日常、通勤、健身和聚会四个场合入口；
- 单件衣物可多选适用场合，新增衣物默认日常；日常展示完整衣橱，通勤、健身和聚会排除不符合标签的单品；
- “帮我选”优先场合专用单品，“自己搭”保留跨场合混搭自由；
- 锁定一件单品后只查看包含它的组合；
- 按较少穿、同场合历史或最常穿排序；
- 每次显示 6 套并支持“换一批”；
- 最多计算 2,000 个候选，避免大衣橱阻塞手机页面；
- 穿搭记录保存场合，为后续个性化排序积累数据。
- 上装增加贴身层、保暖中层和普通单穿层级，组合可以同时包含秋衣、毛衣与外套；
- 双模式穿搭：“帮我选”用于快速决策，“自己搭”支持任意核心单品和动态下一槽位；
- 自己搭按主体、贴身层、保暖中层、外套、鞋履、包袋和配饰逐步推进，必要主体不可跳过，可选层次可以跳过；

## 下一阶段

### 已完成：个人物品档案入口 V0.3

- 一级导航调整为“物品库｜怎么用｜关于它｜数据与备份”；
- 物品库以衣物、其他物品和数码为大品类；“怎么用”入口依次为衣物、数码、其他；
- “其他”已支持同一天多次记录，并提供 30 天使用次数、使用覆盖率、使用间隔、待处理列表、状态变化与简单维护时间线；
- 单件物品增加可选“关于它”，支持集中回看、补写和搜索；
- 故事卡可在本地预览并保存 PNG，默认不包含金额和收纳位置；
- 完整备份包含故事，并兼容缺失故事字段的旧备份。

待验证用户能否找到新入口、是否愿意补写与回看，以及故事卡是否成功保存。数码状态、保修和借还等类型化事件仍属于后续范围；其他物品的覆盖率与待处理提示已实现，统计口径和维护记录是否有用仍需真实用户验证。

## 当前不优先

- 原生 iOS/Android App；
- 社交社区；
- 虚拟试穿；
- 完整电商或二手交易市场；
- 大规模模型微调；
- 没有用户验证的复杂仪表盘。

## 决策门槛

完成两轮定向验证后，如果 20 位目标用户中没有 3 位完成至少 3 件录入，也没有明确的高频场景或付费表达，暂停完整产品开发，保留现有 MVP。
